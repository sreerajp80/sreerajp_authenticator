# Localization foundation (adoption Phase 5, Part 5a)

Implements Part 5a of plan: `plans/20261029_202317_localization-phase-5.md`
(part of `plans/20261029_183929_adopt-updated-guidelines.md`, Phase 5)

## What changed

### Setup
- `pubspec.yaml` — added `cupertino_ui: ^1.1.4`, `flutter_localizations` (SDK), `intl: ^0.20.3`;
  `flutter: generate: true`; font families `NotoSansMalayalam` and `NotoSansDevanagari`
  (Regular, Bold). `pubspec.lock` updated by `flutter pub get`.
- `l10n.yaml` (new) and `lib/l10n/app_en.arb`, `app_ml.arb`, `app_sa.arb` (new, 83 keys each);
  `lib/l10n/app_localizations*.dart` generated by `flutter gen-l10n`.
- `lib/l10n/fallback_localizations.dart` (new) — Material / Cupertino / Widgets fallback
  delegates: `sa` loads English framework strings (never Hindi).
- `lib/config/locale_config.dart` (new) — supported locales, the delegate list (fallbacks first,
  then `GlobalMaterialLocalizations.delegates` from `material_ui`), endonyms, device-locale
  resolution, `formattingLocale(...)`.
- `lib/providers/locale_provider.dart` (new) — `app_language` = `system` / `en` / `ml` / `sa`.
- `lib/main.dart` — reads the saved language and the About config before `runApp`; provides
  `LocaleProvider` and `AppConfig`; `MaterialApp` gets `locale`, `supportedLocales`,
  `localizationsDelegates`, `localeResolutionCallback` and `onGenerateTitle` (app name in the
  active language). The splash shows the app name from the config as one line (it was split into
  "Sreeraj P" / "Authenticator", which does not work in other languages) and its loading text
  from ARB.
- `lib/utils/theme.dart` — `fontFamilyFallback` (Noto Malayalam, Noto Devanagari) in both themes;
  heart token `heartRed = #E53935`.
- Fonts copied from the owner's other projects (no download): `fonts/NotoSansMalayalam-*.ttf`
  and `fonts/NotoSansDevanagari-*.ttf` from SreerajP Journal Vault; `fonts/OFL-NotoSansMalayalam.txt`
  and `fonts/OFL-NotoSansDevanagari.txt` from SreerajPContactSphere (Journal Vault has only one
  combined `OFL-Noto.txt`); `fonts/OFL-Inter.txt` from MantraJapaCounter.

### Screens
- `lib/screens/language_settings_screen.dart` (new) — System default, `English`, `മലയാളം`,
  `संस्कृतम्`, each with its name in the active language; the selected option is marked; the
  change applies at once.
- `lib/screens/settings_screen.dart` — all text from ARB; new Language row (current value,
  screen-reader label "Language: …").
- `lib/screens/appearance_screen.dart`, `theme_mode_settings_screen.dart` — all text from ARB.
- `lib/screens/about_screen.dart` — all text from ARB; name, description and row values resolved
  for the active language; row labels from `aboutDetail<Key>`; `website` and `privacyPolicy`
  rows open the browser; ends with the badge.
- `lib/widgets/made_with_love.dart` (new) — the badge: localized text, red vector heart,
  `Semantics(label: madeWithLoveA11y)`.

### Config and constants
- `lib/config/app_config.dart` — `LocalizedText`; `appName`, `description` and `details` values
  are locale maps or plain strings; the fallback app name is in all three languages.
- `assets/config/app_config.json` — locale maps; `lowerCamelCase` keys (`author`, `email`,
  `website`, `privacyPolicy`, `license`, `aiUsed`, `ideUsed`); `website` and `privacyPolicy` added.
- `lib/utils/constants.dart` — About-screen UI text and the unused `developerInfo` /
  `AboutInfoEntry` removed; `appNameProd` / `appNameDev` renamed.

### Android
- `android/app/build.gradle.kts` — `bundle { language { enableSplit = false } }`; the
  `appName` manifest placeholders removed.
- `android/app/src/main/AndroidManifest.xml` — `android:label="@string/app_name"`.
- `android/app/src/{dev,prod}/res/values{,-ml,-sa}/strings.xml` (new) — launcher name per
  flavor and language (dev adds " Dev"). Checked in the merged `devDebug` resources.

### Docs

## Problems met while working
- The Hindi-marker gate matches plain substrings, so the correct Sanskrit word `सङ्ग्रहाः`
  ("collections") was flagged because it contains `रहा`. The licence text now uses `ग्रन्थाः`.
- In the About widget test, `rootBundle` cached the config asset in the first test's zone, so the
  next tests waited forever. The test now clears the bundle cache in `setUp`.
