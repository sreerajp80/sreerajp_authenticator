# Fix HOTP codes

Implements plan: `plans/20261030_185703_fix-hotp-codes.md`

**Security impact:** small. The HOTP counter is saved before a code is shown, so a code is never
shown twice. Secret handling, permissions and network use do not change.

## What changed

### Services
- `lib/services/otp_service.dart`
  - New `generateHOTPAsync(account)`: decrypts the secret if needed, then makes the code for the
    stored counter.
  - `generateOtpAuthUri` writes `otpauth://hotp/…&counter=C` for HOTP accounts, with no `period`.
  - The QR parser refuses an HOTP code with a negative counter (returns `null`).
- `lib/services/database_service.dart`: new `setHotpCounter(id, expected, next)`, one parameterized
  `UPDATE`. It changes HOTP rows only, so mOTP PINs in the same column are safe, and a stale
  `expected` value changes nothing. A null counter counts as 0.

### Provider
- `lib/providers/account_provider.dart`: new `nextHotpCode(account)`. It makes the code, saves the
  next counter, updates that account in the list and notifies. If the save fails or the counter has
  already moved, it returns a failure and no code.

### Account tile
- `lib/widgets/account_tile.dart`: HOTP accounts no longer call `generateTOTP` or start timers. The
  countdown ring is replaced by an icon button with a localized tooltip ("Next code"). It is disabled
  while a request runs and hidden in selection mode.
- The tile shows dashes until the first tap in a session. The new code is shown straight away, and
  the existing 28-second auto-hide applies. The code is gone after a lock, because the lock screen
  replaces the tile.
- Copying before the first tap shows "Tap the next code button first."
- Other account types do not change.

### Text
- 3 new keys and 8 changed keys in `lib/l10n/app_{en,ml,sa}.arb`; generated files rebuilt.
- **Beyond the plan's key list:** `descFeatures12` ("Counter: not yet") and `descFeatures13` ("Prefer
  TOTP") also had to change, because they said HOTP does not work.

### Tests
- `test/services/otp_service_test.dart`: URI round trip, negative counter, async RFC 4226 values.
- `test/services/database_service_test.dart`: moves a counter, null counts as 0, stale value changes
  nothing, mOTP PIN never changes.
- `test/providers/account_provider_test.dart`: tapping gives the RFC values and the counter is saved;
  a stale save gives no code. The test covers a counter that has already moved, not a database error.
- New `test/widgets/account_tile_hotp_test.dart` in `en`, `ml`, `sa` at 360 pixels wide: no ring,
  dashes first, the copy message, a tap shows the RFC code and saves the counter.

### Docs
- `docs/features.md`: HOTP row, tile line, and manual entry lines (HOTP is QR only).
- `docs/security.md`: a note on saving the counter before showing the code.
- `README.md` and `docs/architecture.md` checked: their HOTP lines are now true, so no change.

## Checks

- `dart format`: no changes left.
- `flutter analyze`: no issues.
- `flutter test`: 349 tests pass.
- `flutter build apk --flavor dev --debug`: built. Gradle daemons stopped afterwards.
- Not checked: a real HOTP service, or the button on a real phone. The RFC 4226 values are the check.

## Notes

- **Found, not fixed:** the home screen always passes `onTap` to `AccountTile`, and the tile turns off
  double-tap copy when `onTap` is set. So `_copyToClipboard` cannot be reached from the home screen,
  for any account type, even though the help text and `docs/features.md` describe copying. The
  "Tap the next code button first" message is tested on the tile alone. This needs its own fix.
- Each tap uses up one code. Services accept only a small window of later counters; the help text
  warns about this.
