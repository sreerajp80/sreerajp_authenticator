# Change log: package updates after the Flutter 3.50.1 upgrade

Implements plan: `plans/20261127_203142_package-updates.md`

## What changed

### Minor / patch updates (`flutter pub upgrade`)

38 packages moved to newer versions inside their existing constraints, including
`material_ui` 1.11.1, `cupertino_ui` 1.1.7, `file_picker` 13.4.1, `flutter_svg` 2.5.1,
`sqflite` 2.4.6, `sqflite_common_ffi` 2.4.7 (dev) and about 30 transitive packages.

`pubspec.yaml` lower bounds were raised to match: `material_ui: ^1.11.1`,
`cupertino_ui: ^1.1.7`, `file_picker: ^13.4.1`, `flutter_svg: ^2.5.1`, `sqflite: ^2.4.6`,
`sqflite_common_ffi: ^2.4.7`.

### Major updates

- `flutter_slidable` 4.0.3 → 5.2.0 (`^5.2.0`). Version 5 moves to the `material_ui` package,
  which the app already uses. No code change was needed in `lib/screens/home_screen.dart`.
- `flutter_zxing` 3.1.0 → 4.0.0 (exact pin kept). Version 4 has a new engine (zxing-cpp 3.2)
  and a new API; the 3.x API still works but is deprecated until 5.0.
  `lib/widgets/qr_camera_view.dart` now uses the new API:
  - imports only `package:flutter_zxing/core.dart` (no longer the full library with the
    old 3.x API and its `readBarcodeImageUrl` network path);
  - decodes each camera frame with `BarcodeReader.readPixels` on the Y (brightness) plane
    of the YUV420 frame, QR codes only, with the same fast settings as before (no rotate,
    invert, downscale or try-harder);
  - starts the decoder early with `warmUpBarcodeEngine(scanner: false)`, not awaited.
    In zxing 4 the warm-up never fails (a broken decoder reports on the first frame), so
    awaiting it gave no early error. Awaiting it also made a widget test hang: the
    package keeps its start-up as one shared `Future`, and a second test waited on a
    `Future` that belonged to the first test's fake-time zone.
  - removed `zx.startCameraProcessing()` / `zx.stopCameraProcessing()` (not needed in 4.x).

### Docs

- `docs/security.md` — the `flutter_zxing` note now says version 4, the zxing-cpp licence,
  and that only `core.dart` is imported. (Small accuracy fix, not listed in the plan.)

### Not changed

- `pointycastle` stays pinned at 3.9.1: 4.0.0 cannot be resolved with the current
  `encrypt` package. Crypto changes need their own plan.
- `screen_protector` is already the newest version; the build still warns that it applies
  the Kotlin Gradle Plugin. A future Flutter version will refuse this.
- `flutter clean` (asked for by the zxing upgrade guide) was not run, because it would
  delete `build/symbols` (release debug symbols). The build worked without it.

## Checks

- Licences: `flutter_slidable` 5.2.0 MIT; `flutter_zxing` 4.0.0 MIT (zxing-cpp Apache 2.0).
  No new HTTP, Firebase, ML Kit, analytics or tracking package came in. New transitive
  packages for zxing are build-hook tools (`hooks`, `code_assets`, `native_toolchain_c`).
- `dart format` — no changes.
- `flutter analyze` — 2 issues, both the known deprecation notices in the generated
  `lib/l10n/app_localizations.dart` (from `flutter gen-l10n`, see the toolchain plan).
  The 14 `flutter_zxing` deprecation notices are gone.
- `flutter test` — all 753 tests pass.
- `flutter build apk --flavor dev --debug` — builds. Gradle daemons stopped, leftover
  daemon processes ended.
