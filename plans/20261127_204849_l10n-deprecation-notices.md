# Clear the 2 deprecation notices in the generated l10n file

**Status:** completed

## What the issue is

After the Flutter 3.50.1 upgrade (plan `plans/20261127_202437_toolchain-upgrade-flutter-3-50-1.md`,
status `partial_completion`), `flutter analyze` reports 2 `deprecated_member_use` notices in
`lib/l10n/app_localizations.dart` (lines 91–92):

- `GlobalMaterialLocalizations` — use the one from `package:material_ui` instead.
- `GlobalCupertinoLocalizations` — use the one from `package:cupertino_ui` instead.

The file is generated by `flutter gen-l10n`. Its `localizationsDelegates` list still names the
old SDK classes, and the 3.50.1 generator has no option to change that. A hand edit would be
lost on the next `flutter gen-l10n`. The app never uses this list: `MaterialApp` uses
`LocaleConfig.localizationsDelegates` (`lib/config/locale_config.dart`), which already takes
the delegates from `material_ui` / `cupertino_ui`.

The file already starts with `// ignore_for_file: type=lint`, but that covers lint rules only;
`deprecated_member_use` is an analyzer warning, not a lint, so it still shows.

## Options considered

| Option | Effect | Downside |
|--------|--------|----------|
| A. `header:` in `l10n.yaml` with `// ignore_for_file: deprecated_member_use` | The generator writes this line at the top of every generated l10n Dart file. Only this one warning, only in generated files. Survives regeneration. | Hides future deprecations in generated l10n files too (they are generated, so we cannot fix them by hand anyway). |
| B. Exclude `lib/l10n/app_localizations*.dart` in `analysis_options.yaml` | No analysis of generated files at all. | Too wide: real errors in generated files (e.g. a bad ARB placeholder) would also be hidden from `flutter analyze`. |
| C. Turn off `deprecated_member_use` for the whole project | — | Hides real deprecations in our own code. Not acceptable. |
| D. Hand-edit the generated file | — | Lost on the next `flutter gen-l10n`. Not acceptable. |

Recommended: **A**.

## Files to change

1. `l10n.yaml` — add
   `header: "// ignore_for_file: deprecated_member_use"` with a short comment saying why
   (the generated `localizationsDelegates` list names the old SDK delegates; the app uses
   `LocaleConfig.localizationsDelegates`).
2. `lib/l10n/app_localizations.dart`, `app_localizations_en.dart`, `app_localizations_ml.dart`,
   `app_localizations_sa.dart` — regenerated by `flutter gen-l10n` (not edited by hand).

## Plan for the fix

1. Edit `l10n.yaml`.
2. Run `flutter gen-l10n`.
3. Run `dart format .`, `flutter analyze` (target: zero issues), `flutter test`.
4. No Gradle build needed (Dart-only change).
5. Write the change log. It also closes the open item of the toolchain plan.

## Security impact

None. Analyzer setting for generated localization files only. No change to runtime code,
permissions, network, storage or dependencies.
