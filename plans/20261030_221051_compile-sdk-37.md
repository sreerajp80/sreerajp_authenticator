# Compile against Android SDK 37

**Status:** completed

## Files to change

- `android/app/build.gradle.kts` (one line)

## Issue

The prod release build fails at `checkProdReleaseAarMetadata`. `permission_handler_android`, brought
in by `permission_handler` 13, requires apps to compile against Android SDK 37. The app uses
`flutter.compileSdkVersion`, which is 36 in Flutter 3.47.6.

## Fix

In the `android` block, change:

```kotlin
compileSdk = flutter.compileSdkVersion
```

to:

```kotlin
// permission_handler 13 needs 37; Flutter's default is still 36.
compileSdk = 37
```

`targetSdk` stays at `flutter.targetSdkVersion` (36) and `minSdk` stays at 29. `compileSdk` only
sets which Android APIs the code can see when it is built. It does not turn on new Android
behaviour on phones, and it does not change which phones can install the app.

When Flutter's own default reaches 37 or higher, this line can go back to
`flutter.compileSdkVersion`.

## Security impact

Platform folder change, build setting only. No change to permissions, the manifest, or the
behaviour of the app on phones.

## Verification

1. Build the prod release again, then stop the Gradle daemons. Android SDK platform 37 is already
   installed on the build machine, so no download is expected.
2. Do the phone checklist in `plans/20261030_220101_file-picker-13-api.md`.
