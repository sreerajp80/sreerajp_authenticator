# Turn on built-in Kotlin

**Status:** completed

Replaces `plans/20261030_221258_pin-screen-protector.md`.

## Files to change

- `android/gradle.properties` (one flag, and its comment)
- `android/app/build.gradle.kts` (one comment only)

## Issue

The prod release build fails with "cannot find symbol: ScreenProtectorPlugin".

`screen_protector` 1.5.3 applies the Kotlin plugin only on the Android Gradle Plugin (AGP) older
than 9, because it expects AGP 9 to compile Kotlin by itself. This project uses AGP 9.4.1 with
`android.builtInKotlin=false`, so nothing compiles that plugin's Kotlin file.

## Fix

1. In `android/gradle.properties`, replace:

   ```properties
   # This builtInKotlin flag was added automatically by Flutter migrator
   android.builtInKotlin=false
   ```

   with:

   ```properties
   # AGP compiles Kotlin itself. Check each Android plugin before changing this.
   android.builtInKotlin=true
   ```

2. In `android/app/build.gradle.kts`, replace the comment in the `plugins { }` block that says Kotlin
   is applied by the Flutter Gradle plugin, because that stops being true.

These stay as they are:

- `id("org.jetbrains.kotlin.android") version "2.4.10" apply false` in `android/settings.gradle.kts`.
  It keeps that Kotlin version on the build classpath, and AGP uses it. The
  `flutter_build_flavors_guide.md` guideline says to keep it.
- The `kotlin { compilerOptions { } }` block in `android/app/build.gradle.kts`. The engineering
  standard asks for this form.
- `android.newDsl=false`, which is a separate migration.
- `kotlin.incremental=false`, the workaround for the pub cache and project being on different
  drives.

## Plugin check

The guideline requires this first: a plugin that always applies the Kotlin plugin breaks the build.
All 16 Android plugins in `.dart_tool/package_config.json` were checked:

| Group | Plugins | Result |
|---|---|---|
| Skip Kotlin when built-in is on | `android_file_picker`, `package_info_plus`, `share_plus`, `screen_protector` | Fine |
| Never apply Kotlin in their build file | `camera_android_camerax`, `image_picker_android`, `local_auth_android`, `shared_preferences_android`, `url_launcher_android` | Fine |
| No Kotlin source | `flutter_plugin_android_lifecycle`, `flutter_secure_storage`, `flutter_zxing`, `jni`, `jni_flutter`, `permission_handler_android`, `sqflite_android` | Fine |

No plugin always applies the Kotlin plugin. This check reads build files only. Only a real build
proves the result.

## Rollback

Set `android.builtInKotlin=false` again. The app module does not need `kotlin-android` added back,
because the Flutter Gradle plugin applied it before.

## Security impact

Platform folder change, build setting only. The compiled Kotlin source does not change, and there
is no change to permissions or dependencies. `screen_protector` stays at 1.5.3, so screenshot
blocking must be checked on a phone.
