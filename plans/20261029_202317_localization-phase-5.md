## What the issue is

`docs/PROJECT_PROFILE.md` §4 declares English (`en`, template), Malayalam (`ml`) and Sanskrit
(`sa`). The engineering standard §8 and the language pack
`docs/guidelines/language_packs/sanskrit_malayalam.md` require:

- `l10n.yaml` and one ARB file per language; every user-visible string from `AppLocalizations`
  (§8.1, §8.2).
- A real translation for every key in every language; a parity test that fails otherwise (§8.7).
- A fallback delegate so Flutter's own widgets work under `sa` (no framework translation), with a
  widget test (§8.3.1, pack §1.1).
- `formattingLocale(...)` for dates and numbers (§8.3.2).
- Fonts that cover Malayalam and Devanagari (§8.3.3, pack §2).
- An in-app language picker: System default + `English` / `മലയാളം` / `संस्कृतम्`, saved, read
  before the first frame, applied without restart (§8.4, pack §3).
- Short labels within 22 characters, key prefixes, a length test (§8.6, pack §5).
- Sanskrit that is real Sanskrit, with the Hindi-marker check (pack §4.1).
- Android App Bundle language splitting off (§8.1).
- About screen from `app_config.json` locale maps, row labels from ARB (`aboutDetail<Key>`), a
  privacy-policy row, and the badge "Made with {heart} in India" (`guideline.md` §1.2, §1.6, §1.7).
- The OS app name per language (`guideline.md` §1.8).

Today none of this exists. A count of `lib/` finds about **980 user-visible string literals**:

| Area | Approx. strings |
|---|---|
| `features_screen.dart` + 9 help screens (long prose) | ~260 |
| Security, lock, backup/restore, PIN dialog | ~190 |
| Home, add account, QR scanner, account widgets, tags, permissions | ~200 |
| Sync screens (Wi-Fi, send to device, optical, sync QR) | ~100 |
| Settings, appearance, theme, about, `main.dart`, `constants.dart` | ~95 |
| Messages built in services / providers (`otp_service`, `p2p_sync_service`, …) | ~105 |

Some of these are technical (algorithm names, URI parts) and will stay literals. Messages built in
services break the layer rule (services must not hold UI text), so they become error codes or
enums that the UI maps to `AppLocalizations`.

## How the work is split

This is too large for one change. Phase 5 has four parts. **Approving this plan approves Part 5a
only.** Parts 5b–5d each get their own short plan (list of screens, keys, and any service changes)
and approval.

| Part | Scope |
|---|---|
| **5a — Foundation** (this plan, detailed below) | Setup, picker, fonts, About, tests, plus Settings / Appearance / Theme / About / `main.dart` strings |
| 5b — Core flows | Lock, home, add account, QR scanner, account tile widgets, tag widgets, PIN dialog, permissions |
| 5c — Security, backup and sync | Security, backup/restore, tag management, all sync screens; service and provider messages → codes |
| 5d — Long text | Features screen and the 9 help screens |

Until 5d is done, screens not yet migrated still show English under `ml` and `sa`. The parity test
checks only keys that exist, so it passes; `CLAUDE.md` already says the migration is in progress.
