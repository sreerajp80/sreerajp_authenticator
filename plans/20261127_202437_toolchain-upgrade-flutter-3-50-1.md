# Toolchain upgrade: Flutter 3.50.1, Kotlin 2.4.20

**Status:** partial_completion

## What the issue is

The user asked to move the project to Flutter 3.50.1, AGP 9.4.1, Gradle 9.8.0 and Kotlin 2.4.20.

Current state found in the repository:

| Tool | Now | Target | Change needed? |
|------|-----|--------|----------------|
| Flutter SDK | 3.47.6 (pinned in CI and docs) | 3.50.1 | Yes |
| Dart SDK constraint | `^3.13.5` | `^3.14.0` (Dart in Flutter 3.50.1) | Yes (see note) |
| AGP | 9.4.1 | 9.4.1 | No — already there |
| Gradle wrapper | 9.8.0 | 9.8.0 | No — already there |
| Kotlin Gradle Plugin | 2.4.10 | 2.4.20 | Yes |

Flutter 3.50.1 (Dart 3.14.0) is already installed on the build machine, so only the project
files and docs need to change.

## Files to change

1. `android/settings.gradle.kts` — Kotlin plugin `2.4.10` → `2.4.20`.
2. `pubspec.yaml` — `environment.sdk: ^3.13.5` → `^3.14.0`.
3. `pubspec.lock` — regenerated by `flutter pub get` (never edited by hand).
4. `.github/workflows/ci.yml` — `flutter-version: 3.47.6` → `3.50.1`.
5. `CLAUDE.md` — project identity table: Flutter SDK, Dart SDK, Kotlin version.
6. `AGENTS.md` — same table as `CLAUDE.md`.
7. `README.md` — Flutter badge and "3.47 stable" text → 3.50.

Not changed:
- `android/gradle/wrapper/gradle-wrapper.properties` and the AGP line — already at target.
- `docs/implementation_progress.md` — it is a history record of Phase 3; it stays as it was.

## Plan for the fix

1. Edit the files listed above.
2. Run `flutter pub get` (updates `pubspec.lock`).
3. Run `dart format .`, `flutter analyze` (must be zero issues) and `flutter test`.
4. Fix any new analyzer warnings or deprecations Flutter 3.50 brings, if they appear
   (these fixes are reported back to the user first if they are more than small, mechanical ones).
5. Do one Gradle build (`flutter build apk --flavor dev --debug`) to prove Kotlin 2.4.20 and
   AGP/Gradle work together.
6. Run `android\gradlew --stop` and end any leftover `GradleDaemon` / `KotlinCompileDaemon`.
7. Write the change log in `change_log/`.

Note on the Dart constraint: raising it to `^3.14.0` means anyone on Flutter older than 3.50
cannot build the project. That matches the pinned CI version. Keeping `^3.13.5` is also valid
and less strict; the choice is the user's.

## Security impact

Build tooling only (platform folder `android/` and the Dart SDK). No change to permissions,
network use, storage, or dependencies list. Transitive package versions may move inside
`pubspec.lock` after `flutter pub get`; these are checked against `docs/dependencies.md`.
