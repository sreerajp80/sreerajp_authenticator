# Update backup import to the file_picker 13 API

**Status:** completed

## Files to change

- `lib/services/export_import_service.dart` (only `importAccountsEncrypted`)

## Issue

`pubspec.yaml` moved `file_picker` from `^10.3.3` to `^13.3.0`. The release build now fails with
"Member not found: 'platform'" because version 12 removed `FilePicker.platform`.

Version 12 also removed `FilePickerResult`. `pickFiles()` now returns a plain list, and an empty
list when the user cancels, so `result == null` and `result.files` in the same method are also out
of date. This is the only place in `lib/` that uses `file_picker`.

## Fix

Use `FilePicker.pickFile()`. It picks one file and returns `null` on cancel, so the "cancelled"
behaviour the caller depends on stays the same:

```dart
final picked = await FilePicker.pickFile(
  type: FileType.custom,
  allowedExtensions: ['aes'],
);

if (picked == null) {
  return null;
}

final path = picked.path;
if (path == null) {
  throw const BackupPasswordException();
}

return readBackupFile(File(path), password);
```

`readBackupFile` does not change, so the size limit and the decrypt checks stay as they are.

## What stays the same on purpose

If `path` is `null`, the code still throws `BackupPasswordException`, as it does today. The Android
code in the package copies a picked file to the app's cache and returns a normal file path, so this
should be rare. This plan does not change that error message.

## Security impact

Backup import only. The picked file is still untrusted, and it still goes through the same size
check, decryption and validation. No new permission, and no new or changed dependency in this plan.

## Other updated plugins

`flutter analyze` reports this as the only error in the project. Before this fix, 4 test files
fail to load. One was confirmed to fail on this same error, and the others should clear with it.
No other code change is planned. The analyzer cannot see behaviour changes, so the phone test
below also covers the plugins with major updates.

## Verification

1. `dart format .`, `flutter analyze` and `flutter test`. The existing tests in
   `test/services/export_import_file_limits_test.dart` cover `readBackupFile`, but not the picker.
2. Build the prod release again, then stop the Gradle daemons. This build may show Android-side
   problems the analyzer cannot see, because the earlier build stopped before that stage. Some
   updated plugins now ask for compileSdk 37.
3. On a real phone, install over the existing app (do not uninstall first), then check:
   - existing accounts still open and show codes (`flutter_secure_storage` 10 to 11),
   - import a real backup, and also open the picker and cancel it (`file_picker`),
   - export a backup through the share sheet (`share_plus`),
   - scan a QR code after granting camera permission (`permission_handler`),
   - screenshots stay blocked (`screen_protector`).
