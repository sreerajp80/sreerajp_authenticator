# Package updates after the Flutter 3.50.1 upgrade

**Status:** completed

## What the issue is

After moving to Flutter 3.50.1 (plan `plans/20261127_202437_toolchain-upgrade-flutter-3-50-1.md`),
`flutter pub outdated` shows many packages with newer versions. The user asked to update the
packages and then test and analyse again.

The updates fall into three groups:

**A. Minor / patch updates (no `pubspec.yaml` change needed, only `pubspec.lock`):**

| Package | Now | New |
|---------|-----|-----|
| `material_ui` | 1.9.0 | 1.11.1 |
| `cupertino_ui` | 1.1.5 | 1.1.7 |
| `file_picker` | 13.3.0 | 13.4.1 |
| `flutter_svg` | 2.3.2 | 2.5.1 |
| `sqflite` | 2.4.5 | 2.4.6 |
| `sqflite_common_ffi` (dev) | 2.4.5 | 2.4.7 |
| about 30 transitive packages | — | patch/minor bumps |

**B. Major updates (need a `pubspec.yaml` change and may break code):**

| Package | Now | New | Used in |
|---------|-----|-----|---------|
| `flutter_slidable` | 4.0.3 (`^4.0.3`) | 5.2.0 | `lib/screens/home_screen.dart` |
| `flutter_zxing` | 3.1.0 (exact pin) | 4.0.0 | `lib/widgets/qr_camera_view.dart` |

**C. Not updated:**
- `pointycastle` stays at the exact pin `3.9.1`. Version 4.0.0 exists, but pub cannot
  resolve it (another package, most likely `encrypt`, still needs 3.x). Crypto code is
  security-critical, so it moves only in its own planned change.
- `screen_protector` is already the newest version, so the Kotlin Gradle Plugin build
  warning cannot be fixed by an update today.

## Files to change

1. `pubspec.yaml` — `flutter_slidable: ^5.2.0`, `flutter_zxing: 4.0.0` (keep exact pin style).
   Lower bounds for group A raised to the new versions (`material_ui: ^1.11.1`,
   `cupertino_ui: ^1.1.7`, and the others if listed with a caret).
2. `pubspec.lock` — regenerated by `flutter pub upgrade` / `flutter pub get` only.
3. `lib/screens/home_screen.dart` — only if `flutter_slidable` 5 changed its API.
4. `lib/widgets/qr_camera_view.dart` — only if `flutter_zxing` 4 changed its API.
5. `docs/dependencies.md` — only if a package's role or licence changed.

## Plan for the fix

1. Run `flutter pub upgrade` (group A).
2. Read the changelogs of `flutter_slidable` 5.x and `flutter_zxing` 4.0.0 (pub.dev).
   Check that the licence is still open source and that no new network / tracking package
   came in as a transitive dependency (`docs/dependencies.md` blocked list).
   If either major update needs large code changes, stop and report back before doing it.
3. Edit `pubspec.yaml` for group B and the raised lower bounds, then `flutter pub get`.
4. Fix small API changes in the two files above, if any.
5. Run `dart format .`, `flutter analyze`, `flutter test`.
6. Build the dev debug APK once (`flutter build apk --flavor dev --debug`), because
   `flutter_zxing` has native code. Then `android\gradlew --stop` and end leftover
   `GradleDaemon` / `KotlinCompileDaemon` processes.
7. Ask the user to test QR scanning and swipe actions on a real phone (tests cannot cover
   the camera).
8. Write the change log.

Note: `flutter analyze` will still show the 2 deprecation notices in the generated
`lib/l10n/app_localizations.dart` from the toolchain plan. Package updates do not fix them
(they come from the `flutter gen-l10n` tool). That item is still open in the toolchain plan.

## Security impact

Dependency change. `flutter_zxing` parses untrusted QR data with native code, so its
update is checked for licence, new transitive packages and API changes. No change to
permissions, network use or storage. `pointycastle` (crypto) is not touched.
